## 2. Живые фреймы решений (T14)

По результатам замеров 200 запросов на `qwen3.5-9b` (SDK + ограниченный GBNF) и `gemma-4-12b-coder` (HTTP freeform):

- **Кластерные типы (HANDOFF, RES, QUERY, ERR)**:
  - `qwen9b`: strict 80/80 = 100 %, accept 100 %, sem 100 %, p95 генерации $\le$ 5.45 с.
  - `gemma`: strict 72/80 = 90 %, lenient 100 %, accept 100 %, sem 100 %, p95 генерации $\le$ 12.45 с.
- **Оговорка по gemma RES**: strict 12/20 = 60 %. Модель первой строкой выводит корректный фрейм, но на второй строке добавляет причину текстом (`STALLED`). Фрейм принимается приёмником только в lenient-режиме (через `extract_frame`). Для строгого режима необходима стоп-последовательность `\n` в запросе к серверу.
- **Военный профиль PROP**: оставлен как справочный, не входит в порог кластера (qwen9b sem 17/20 = 85 %, gemma sem 18/20 = 90 %).

## 3. Транспортная шина кластера

- `scripts/aml_bus.py` реализует надёжную доставку через outbox-файлы с разделителем `\n\n`.
- Приёмник `agent_sync serve` каждые 0.5 с выполняет: `validate_frame` $\rightarrow$ `Receiver.accept` $\rightarrow$ проверку полномочий по `board.json` (§4.1).
- Задержка доставки: p95 = 0.51 с (при пороге 2.0 с).
- Вердикты локальных моделей регистрируются со статусом «совет модели» и не меняют состояние доски напрямую.
