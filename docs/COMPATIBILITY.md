# Совместимость: выпуск r2 (24.09.2026)

Комплект r2 развивает AML/NAM как компактный протокол межагентного обмена (A2A wire protocol) для кластера агентов и локальных моделей.

Маркер протокола `!AML:2|` сохранён. Добавлен профиль кластера `s:2`, изолированный от базового военного словаря.

## 1. Профиль кластера `s:2` (T37)

Для публикации состояния доски, статусов агентов и управляющих предложений используется расширение NAM/2 `s:2`:

```text
!AML:2|STATE|aml-nam|agent_sync→claude|4|1790200000000|30000|s:2|w:board|r:4
#T13:task:INP:antigravity:codex:P1:t999500:dep:#T17,#T18
#codex:agent:ACT:L72:W45:t999500:tsk:#T34
```

### Строки сущностей
- **Задача (`task`)**: `#<id>:task:<STATUS>:<assignee>:<critic>:P<priority>:t<ms>:dep:<deps>`
  - Статусы: `BKL` (backlog), `INP` (in_progress), `REV` (review), `APR` (approval/claude), `DON` (done), `CLS` (closed).
- **Агент (`agent`)**: `#<name>:agent:<STATE>:L<limit>:W<weekly>:t<ms>:tsk:<task>`
  - Состояния: `ACT` (active), `STL` (stale), `WAT` (watching/paused), `OFF` (offline).
  - Лимиты: `L<pct>`, `W<weekly_pct>` (или `-` если неизвестно).

### Действия в PROP
- `RSG` — переназначить (валидатор проверяет, что новый исполнитель доступен и не является критиком);
- `PAU` / `RSM` — пауза и возврат агента;
- `RTN` / `APV` — возврат задачи на доработку или финальная приёмка куратором.
- Причины (`rs:`): `LIMIT`, `STALE`, `CRITIC_RETURN`, `DEPENDS`.

### Изоляция профилей (Profile Gating)
- Фреймы с маркером `s:2` отклоняют тактические сущности и действия военного профиля (`INF`, `REC`, `ASSAULT`, `SET_ROE` и др.).
- Фреймы без маркера `s:2` отклоняют строки задач, агентов и действия управления кластером.
- Смешивание словарей в одном фрейме вызывает `AMLError` при кодировании/валидации.

## 2. Шина кластера (`scripts/aml_bus.py`)

- **Разделитель фреймов**: два перевода строки (`\n\n` или `\r\n\r\n`). Приёмник не читает незавершённый срез файла, ожидая полного окончания записи фрейма отправителем (T35 F1).
- **Полномочия по задаче**: определяются по состоянию `board.json` в момент приёма, а не из текста сообщения:
  - `HANDOFF COMPLETE` принимается только от текущего исполнителя задачи в статусе `in_progress`;
  - `RES` вердикты принимаются только от назначенного критика (в статусе `review`) или куратора (в статусе `claude`);
  - Локальные модели (`qwen9b`, `gemma`) принимаются со статусом «совет модели» и не меняют доску напрямую.
- **Отказы**: фиксируются кодами `INVALID`, `UNAUTHORIZED`, `EXPIRED`, `REPLAY` с записью в лог и отправкой почты отправителю.

## 3. Клиенты и локальные модели (T12, T13, T14)

- **LM Studio 0.4.x**:
  - При вызове через SDK (`scripts/llm_client_sdk.py`) принудительное применение GBNF подтверждено. Для reasoning-моделей размышления отсекаются по сепаратору `</think>`.
  - HTTP-эндпоинт `/v1/chat/completions` игнорирует поле `grammar`. Клиент `scripts/llm_client.py` работает по принципу fail-fast / fail-closed: без предварительно подтверждённой пробы грамматики запрос отклоняется с `AMLError` (для запросов без грамматики используйте `--no-grammar`).
  - Результаты пробы кэшируются на процесс по паре `(endpoint, model)` с полной изоляцией в тестах (T13 F4).
- **Межпроцессный мост**: вызовы Python↔Node на Windows выполняются с явным декодированием UTF-8 (T11).

## 4. Базовый профиль (унаследовано из r1)

- **RESULT**: обязательное поле `related`, унифицированный формат маркеров (`ACC`, `EXEC`, `REJ`, `FAIL`), опциональная причина `|rs:CODE[#evidence,...]`.
- **Частичные обновления**: запрещены пустые updates; частичное обновление не обновляет `observed_ms` (новое наблюдение требует полного upsert); явный `null` в partial отклоняется кодировщиком.
- **Поля вне проекции**: непредставимые поля (`side`, нестандартные id, float точнее 0.01) вызывают `AMLError`; в таких случаях используется NAM JSON.
