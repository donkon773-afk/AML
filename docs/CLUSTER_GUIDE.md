# Руководство: обмен сообщениями по AML в кластере агентов

Для кого: облачный агент (claude, codex, antigravity и новые) или локальная
модель, которые работают через доску `aml-nam`. Все примеры ниже сгенерированы
`scripts/aml_bus.py` и проходят `validate_frame` + `Receiver.accept`.
Подробности и обоснования — `docs/SCENARIO-cluster-exchange.md` (T17);
`PY` = путь к Python из AGENTS.md.

## 1. Зачем

- **Меньше токенов.** Эталонный набор фреймов — 919 байт против 1812 в JSON
  (−50 %); снимок реальной доски в профиле кластера — 496 токенов cl100k
  против 891 (−44 %).
- **Проверка до изменения доски.** Каждый фрейм проходит грамматику, схему
  NAM, приёмник (кто, свежесть, повтор) и полномочия по задаче. Ошибочный
  или чужой фрейм доску не меняет.

## 2. Устройство одной строкой

```
агент → .agent-sync/frames/outbox-<имя>.aml → agent_sync serve (раз в 0,5 с)
      → validate_frame → Receiver.accept → роль по board.json → доска, log.md, почта
```

Приёмник один — `agent_sync` (он же адресат всех фреймов). Агент результат
не ждёт: итог приходит в `log.md` и почту, а доска видна в `brief`.

## 3. Фреймы

Заголовок у всех одинаковый:
`!AML:2|<ВИД>|<сессия>|<отправитель>→<адресат>|<seq>|<sent_ms>|<ttl_ms>|…`.
`seq` растёт у каждого отправителя; `ttl_ms` — 60 000 (максимум схемы).
Фрейм заканчивается **пустой строкой**.

**HANDOFF — сдача задачи или находки** (строки `SUM/ART/CHK/NXT` — каждая с новой строки):

```
!AML:2|HANDOFF|aml-nam|antigravity→agent_sync|1|1790219619876|60000|tsk:T14|st:COMPLETE
SUM:"отчёт уточнён по F1/F2"
CHK:verify.py:PASS:"112 Python + 14 JS"
NXT:"critic: codex"
```

Статусы: `PLANNED`, `IN_PROGRESS`, `BLOCKED`, `COMPLETE`. `ART:<путь>:<sha256>` —
артефакт (путь относительный, без `..`; хэш — заявление отправителя, файлы
приёмник не открывает).

**RES — вердикт** (`ACC` принять, `REJ` вернуть; список операций = та же задача):

```
!AML:2|RES|aml-nam|codex→agent_sync|1|1790219619879|60000|rel:T14|*REJ:#T14|rs:CRITIC_RETURN
```

**QUERY — вопрос** (`?STATUS:#T<N>` — статус, `?WHY:#T<N>` — последние заметки):

```
!AML:2|QUERY|aml-nam|claude→agent_sync|1|1790219619884|60000|?WHY:#T18
```

**ERR — отказ или пауза** (`BUSY` — «я на паузе по лимиту»):

```
!AML:2|ERR|aml-nam|codex→agent_sync|2|1790219619893|60000|err:BUSY|rel:T36
```

## 4. Как отправить

Руками фреймы писать не нужно — `aml_bus.py` строит, кодирует и нумерует их сам:

```
PY scripts/aml_bus.py send <имя> handoff T<N> COMPLETE --sum "что сделано" \
      --check "verify.py:PASS:112+14" --art review/<дата>/отчёт.md --next "critic: codex"
PY scripts/aml_bus.py send <имя> res T<N> ACC
PY scripts/aml_bus.py send <имя> res T<N> REJ --rs CRITIC_RETURN
PY scripts/aml_bus.py send <имя> query T<N> status      # или why
PY scripts/aml_bus.py send <имя> err T<N> BUSY
PY scripts/aml_bus.py send <имя> query ALL keyframe   # полный снимок доски вне очереди (T42)
```

Статус задачи можно по-прежнему менять и через `agent_sync.py set` — фреймы
удобнее тем, что их проверяет приёмник, а в `history/T<N>.md` остаётся
полный фрейм.

## 5. Кто что может (полномочия по задаче)

Роль берётся из `board.json` на момент приёма, а не из фрейма.

| Фрейм | Кто | Статус до | Итог |
|---|---|---|---|
| `HANDOFF COMPLETE` | исполнитель | `in_progress` | → `review`, письмо критику |
| `HANDOFF IN_PROGRESS` | исполнитель | `backlog`, `in_progress` | → `in_progress` |
| `HANDOFF BLOCKED` | исполнитель | `in_progress` | статус тот же, заметка, письмо куратору |
| `HANDOFF BLOCKED` | критик | `review` | находки в заметки, письмо исполнителю |
| `RES ACC` / `REJ` | критик | `review` | → приёмка (`claude`) / → `in_progress` |
| `RES ACC` / `REJ` | куратор (claude) | приёмка | → `done` / → `in_progress` |
| `RES` любой | локальная модель | любой | доска не меняется — только совет |
| `QUERY` | любой участник | любой | ответ письмом, доска не меняется |
| `ERR BUSY` | агент о себе | — | агент ставится на паузу |

Кто может слать какие виды: облачные агенты — все четыре; локальные модели
(`gemma`, `qwen9b`) — только `RES` и `QUERY`.

## 6. Если фрейм отклонён

Отказ приходит письмом `ERR <код>: причина` и строкой в `log.md`; доска не меняется.

| Код | Причина | Что делать |
|---|---|---|
| `INVALID` | грамматика/схема, нет задачи, `ops` не совпали с `rel`, неверный статус | отправить через `aml_bus.py send`, проверить id задачи |
| `UNAUTHORIZED` | не твоя роль в задаче, вид фрейма не разрешён, подмена отправителя | `brief` — кто исполнитель и критик сейчас |
| `EXPIRED` | прошло больше 60 с (приёмник не работал) | проверить дашборд :5758, отправить заново |
| `REPLAY` | тот же `seq` второй раз | ничего — первый фрейм уже принят |

## 7. Профиль кластера `s:2` (снимки доски, T37)

Длинные фреймы о состоянии пишет только программа (`agent_sync`), не модель.
Профиль включается полем `s:2` в заголовке и не смешивается с военным словарём:

```
!AML:2|STATE|aml-nam|agent_sync→claude|4|1790200000000|30000|s:2|w:board|r:4
#T13:task:INP:antigravity:codex:P1:t999500:dep:#T17,#T18
#codex:agent:ACT:L72:W45:t999500:tsk:#T34
```

Задача: статус `BKL/INP/REV/APR/DON/CLS`, исполнитель, критик, приоритет, время,
зависимости. Агент: состояние `ACT/STL/WAT/OFF`, остаток лимита 5 ч и за
неделю (`-` — неизвестен), текущая задача. Действия в `PROP`: `RSG`
(переназначить — только на доступного агента, не критика задачи), `PAU`/`RSM`
(пауза/возврат агента), `RTN`/`APV` (вернуть/принять задачу). Публикация доски
этими фреймами — T38. Подключился посреди ленты и получил RESYNC — запроси полный снимок `query ALL keyframe` (T42).

## 8. Ограничения

- TTL 60 с: приёмник (`agent_sync serve`) должен работать; ночью он запущен постоянно.
- Фрейм заканчивается пустой строкой; недописанный хвост приёмник не трогает до конца записи.
- Аутентификация — по имени outbox-файла на одном ПК; для нескольких машин нужна подпись (HMAC), её нет.
- Модели только советуют: их вердикты не меняют доску.
- Задержка приёмника «outbox → log.md»: p95 0,51 с при опросе 0,5 с (порог 2 с; `scripts/bench_bus.py`, T38).
