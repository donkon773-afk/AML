# Сценарий: обмен сообщениями между агентами кластера по AML (T17, черновик)

Автор: claude (куратор), 2026-09-24. Критик: codex. Решение по объёму — за
пользователем (см. «Развилки»). Все фреймы ниже построены и проверены
`scripts/cluster_examples.py` (грамматика Lark + схема NAM + `Receiver.accept`);
вывод прогона — `review/2026-09-24/T17-claude-cluster-examples.txt`.

## 1. Участники и роли

| Участник | Тип | Роль в обмене |
|---|---|---|
| `claude` | облачный агент | куратор: ставит задачи, принимает (`RES *ACC`), спрашивает (`QUERY`) |
| `codex` | облачный агент | критик: вердикт (`RES *ACC/*REJ`) + находки (`HANDOFF st:BLOCKED` с `CHK:…:FAIL`) |
| `antigravity` | облачный агент | исполнитель: сдаёт работу (`HANDOFF st:COMPLETE`), сообщает о паузе (`ERR BUSY`) |
| `gptoss` | локальная модель (LM Studio) | советующий критик-2: только `RES` и `QUERY`, решение не финальное |
| `agent_sync` | программа (пульт :5758) | единственный постоянно работающий приёмник и маршрутизатор; источник STATE/DELTA доски |

Далее — произвольные агенты и модели: участник добавляется строкой в
`PERMISSIONS` приёмника и в `.agent-sync/agents.json`.

## 2. Какие сообщения ходят и кто их источник

Правило из T12 (подтверждено контр-пробами codex): **длинные фреймы пишет
программа, короткие фреймы решений — агент или модель.**

| Событие в кластере | Фрейм | Источник |
|---|---|---|
| исполнитель сдал задачу | `HANDOFF tsk:T<N> st:COMPLETE` + `SUM/ART/CHK/NXT` | агент |
| критик вернул с находками | `HANDOFF st:BLOCKED` + `CHK:F<k>:FAIL:"воспроизведение"` | агент |
| вердикт критика / приёмка куратора | `RES rel:T<N> *ACC` или `*REJ` (`rs:` — причина) | агент / модель |
| вопрос о состоянии или причине | `QUERY ?STATUS:#T<N>` / `?WHY:#T<N>` | агент / модель |
| отказ, пауза по лимиту, повтор | `ERR err:BUSY|INVALID|REPLAY|EXPIRED…` | агент / приёмник |
| снимок доски, пульс и лимиты агентов | `STATE` / `DELTA` | **только программа** (`agent_sync`) — фаза 2 |

Пример (сдача задачи и вердикт; проверено):

```
!AML:2|HANDOFF|aml-nam|antigravity→codex|1|1790200000000|60000|tsk:T13|st:COMPLETE
SUM:"F4: reset кэша грамматики в setUp + addCleanup, тест изоляции"
ART:tests/test_regressions.py:<sha256>
CHK:verify.py:PASS:"71/71 + 14/14, exit 0"
NXT:"critic: codex"

!AML:2|RES|aml-nam|codex→claude|2|1790200601000|60000|rel:T13|*REJ:#T13|rs:STALLED
```

## 3. Что проверяет приёмник

Цепочка приёма та же, что для модели в `llm_client.validate_and_accept`:
`validate_frame` (грамматика Lark + обратное декодирование + схема NAM) →
`Receiver.accept(json, authenticated_peer, now_ms)`:

- отправитель совпадает с аутентифицированным участником (`peer identity mismatch`);
- тип фрейма разрешён этому участнику (`unauthorized kind`): матрица
  `PERMISSIONS` в `cluster_examples.py` — `gptoss` не может слать `HANDOFF`;
- сессия `aml-nam` и адресат совпадают;
- свежесть: `sent_ms + ttl_ms` не истёк (`expired/future frame`);
- монотонный `seq` на отправителя и уникальный id (`replay/out-of-order`);
- для `HANDOFF`: пути артефактов только относительные, без `..`; хэши —
  заявление отправителя, приёмник файлы не открывает и `NXT/SUM` не исполняет.

Все четыре отказа воспроизведены в прогоне (права, TTL, подмена, повтор).

**Аутентификация.** На одном ПК участник = процесс под той же учётной
записью; настоящей аутентификации нет, `authenticated_peer` берётся из
имени файла-отправителя. Для кластера из нескольких машин нужна подпись
фрейма (HMAC на общий секрет, как подпись команд в BlackFox) — вне объёма
первого прототипа.

## 4. Транспорт первого прототипа

**Ограничение схемы:** `ttl_ms ≤ 60 000` (`assets/nam.schema.json`).
Облачные агенты работают циклами по 5–20 минут, поэтому фрейм не может
лежать в почте до следующего цикла агента — он истечёт. Решение:

1. Отправитель дописывает фрейм в `.agent-sync/frames/outbox-<sender>.aml`
   (разделитель — строка, начинающаяся с `!AML:2|`).
2. `agent_sync serve` (уже работает постоянно, T32) раз в 1–2 с читает
   новые фреймы, прогоняет их через `validate_frame` → `Receiver.accept`
   в пределах TTL и применяет: `HANDOFF COMPLETE` → статус `review`,
   `RES *REJ` → `in_progress`, `RES *ACC` от критика → `claude`, от куратора → `done`,
   `ERR BUSY` → пауза агента.
3. Принятый фрейм превращается в человекочитаемую запись `log.md` (как
   сейчас) и строку `events.jsonl`; отвергнутый — в `ERR` обратно отправителю
   и в лог с причиной.
4. Агент читает не фреймы, а свой `brief` (T32) — там уже результат приёма.

Так TTL остаётся коротким (защита от повторов и устаревших решений), а
асинхронность обеспечивает доска.

### 4.1. Полномочия по задаче и таблица переходов (обязательно для T35)

`Receiver.accept` проверяет только общую матрицу «участник × вид фрейма».
Изменить доску фрейм может, **только если отправитель играет по этой задаче
нужную роль в момент приёма** — роли берутся из `board.json` (`assignee`,
`critic`), а не из фрейма. Проверка идёт после `Receiver.accept` и до записи
в доску; при отказе доска не меняется, отправителю уходит `ERR UNAUTHORIZED`
(`rel` = id фрейма), в log.md — строка с причиной.

| Фрейм | Кто вправе | Статус задачи до | Действие | Иначе |
|---|---|---|---|---|
| `HANDOFF st:COMPLETE` | `assignee` | `in_progress` | → `review`; `SUM/CHK/ART` дописываются в notes, полный фрейм — в `history/T<N>.md` | `ERR UNAUTHORIZED` / `ERR INVALID` (не тот статус) |
| `HANDOFF st:IN_PROGRESS` | `assignee` | `backlog`, `in_progress` | → `in_progress`, пульс агента | то же |
| `HANDOFF st:BLOCKED` от исполнителя | `assignee` | `in_progress` | статус не меняется, в notes «blocked: SUM», письмо куратору | то же |
| `HANDOFF st:BLOCKED` от критика | `critic` | `review` | находки `CHK:…:FAIL` → notes и `history/`, письмо исполнителю; статус меняет только парный `RES *REJ` | то же |
| `RES *REJ` (`rel`/ops = T<N>) | `critic` | `review` | → `in_progress` | то же |
| `RES *ACC` | `critic` | `review` | → `approval` (на доске `claude`) | то же |
| `RES *ACC` | `claude` (куратор) | `approval` | → `done` | то же |
| `RES *REJ` | `claude` | `approval` | → `in_progress` | то же |
| `RES` любой | `gptoss` | любой | **доску не меняет никогда**: запись в log.md с пометкой «совет локальной модели» и письмо куратору | — |
| `QUERY ?STATUS/?WHY` | любой из матрицы | любой | ответ `brief`-строкой по задаче, доска не меняется | — |
| `ERR BUSY` | сам агент о себе | — | агент → пауза (как `heartbeat --state paused`) | `ERR UNAUTHORIZED`, если о другом |

Куратор может вернуть задачу и после `RES *ACC` критика (правило AGENTS.md):
это `RES *REJ` от `claude` при статусе `approval`. `RES` без ссылки на
существующую задачу или с `ops`, не совпадающими с `rel`, — `ERR INVALID`.
Эталонный `RES` от `gptoss` в `cluster_examples.py` проверяет только приём
приёмником; влияние на доску — предмет тестов T35 по этой таблице.

## 5. Метрики и пороги (для T14)

| Метрика | Порог «готов к пилоту» | Как считать |
|---|---|---|
| strict-валидность фреймов модели | ≥ 80 % | `validate_frame` без правок текста, знаменатель — все запросы |
| принятие приёмником | ≥ 80 % от strict | `Receiver.accept` с матрицей прав выше |
| семантическое следование | ≥ 90 % | просили вердикт по T<N> — `rel`/`ops` ссылаются ровно на T<N>; ни одной ссылки на несуществующую задачу |
| задержка локальной модели | p95 ≤ 60 с на фрейм ≤ 300 байт | от запроса до готового текста; 60 с — 20 % самого короткого цикла агентов (5 мин) и 5 % длинного (20 мин). При ~3 ток/с у gpt-oss-20b фрейм в 300 байт (~100–150 токенов) укладывается впритык — реальную цифру даст T14 |
| задержка приёмника | p95 ≤ 2 с | от записи в outbox до записи в log.md |
| экономия против JSON | справочно | эталонный набор: 919 / 1812 байт (−50 %) |

Набор T14 для кластера: **HANDOFF, RES, QUERY, ERR** (по ≥ 20 запросов на тип,
вводные — реальные задачи этой доски). PROP остаётся в наборе только для
сопоставимости с T12 на его военном словаре (см. п. 6).

## 6. Что из AML/NAM кластеру не нужно

Словарь STATE/DELTA/PROP создан под Arma 3 и в кластере бессмыслен:
виды сущностей `grp/unt/veh/cnt`, роли `INF/REC/MEC/ARM`, координаты `@x,y`,
метрики `%H…A…S…` (здоровье/боезапас/подавление), позывные, действия
`ADV/ATK/FIRE/…`, `roe/support`, коды причин `CONTACT/LOW_AMMO/PLAYER_ORDER`,
проверка «ungrounded position» в приёмнике.

Нужны и переносятся без изменений: конверт (`session|sender→recipient|seq|
sent_ms|ttl_ms`, `s:`/`tr:` NAM/2), `Receiver` (права, TTL, повтор, ревизии,
`RESYNC`), фреймы `HANDOFF/RES/QUERY/ERR`, грамматика и GBNF для них.

## 7. Развилки для пользователя

1. **Словарь кластера для STATE/DELTA/PROP (фаза 2).** Строки сущностей вида
   `#T13:task:in_progress:antigravity:codex:P1` и `#codex:agent:active:76:45`,
   действия PROP `REASSIGN/PAUSE/RESUME/RETURN`, коды причин `LIMIT/STALE/
   CRITIC_RETURN/DEPENDS`. Это правка грамматики (`aml_grammar.lark`,
   `aml_v2.gbnf`), кодека Python+JS и схемы — отдельная задача, профиль
   через NAM/2 `s:` (payload schema), военный словарь остаётся как профиль 1.
   *Рекомендация:* да, после T35-фазы 1 — без этого доска не выражается в AML.
   **Решение пользователя 24.09: да → T37, реализовано.** Профиль — payload
   schema `s:2` (NAM/2). Строки:
   `#T13:task:INP:antigravity:codex:P1:t<ms>[:dep:#T17,#T18]` (статусы
   `BKL/INP/REV/APR/DON/CLS`), `#codex:agent:ACT:L72:W45:t<ms>[:tsk:#T34]`
   (состояния `ACT/STL/WAT/OFF`, `-` — лимит неизвестен); действия
   `$RSG:#T34:claude:#op1` (REASSIGN, поле `to`), `PAU/RSM` (агент),
   `RTN/APV` (задача); причины `LIMIT/STALE/CRITIC_RETURN/DEPENDS`. Изменения
   профиля — только полными `+`-строками DELTA. Кодек (Python и JS)
   запрещает смешивать словари в одном фрейме и кластерные строки без `s:2`;
   `Receiver` проверяет, что действие направлено на сущность нужного вида,
   а REASSIGN — на доступного агента (`active/stale`), не являющегося
   критиком задачи. Тесты: `tests/test_cluster_profile.py` (10).
   Замер на реальной доске 24.09 (15 задач + 4 агента, один STATE):
   1014 против 2778 байт, cl100k 496 против 891 токена (−44 %), o200k 496 против 863 (−43 %).
2. **TTL.** Оставить ≤ 60 с и принимать через `agent_sync` (рекомендация, п. 4)
   или поднять верхнюю границу схемы для профиля кластера.
3. **gptoss как постоянный участник** (T18): только советующие `RES`, или
   право на `HANDOFF` для небольших задач.

## 8. Прототип (T35, фаза 1 — без правки грамматики)

`agent_sync`: команда `send <sender> <kind> …` строит фрейм через
`AMLCodec.encode`, `serve` принимает outbox'ы по п. 4; дашборд показывает
ленту фреймов. Критерий: один полный круг T<N> исполнитель → критик →
куратор только фреймами, лог читается человеком, `cluster_examples.py
--check` и `verify.py` зелёные, замер байт/токенов фреймов против
эквивалентного JSON на реальном трафике.
