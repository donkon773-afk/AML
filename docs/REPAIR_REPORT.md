# Исправление AML NAM для передачи исходному агенту

Дата: 13 сентября 2026 года. Ревизия: review-fix-r1. Статус: кандидат для интеграционного обзора, не развёрнут.

Подготовлены исправления подтверждённых дефектов, регрессионные тесты и воспроизводимые материалы передачи. Исходный архив и Word-отчёт не изменялись. Этот документ описывает именно новую копию проекта.

## Изменения и доказательства

| Дефект исходника | Изменение | Проверка |
|---|---|---|
| role/count исчезали в partial updates | Парсер правильно потребляет разделённые ключ и значение в Python и JS | Межъязыковой roundtrip и фактическая мутация Receiver |
| null в partial молча терялся | Непредставимое обновление отклоняется; полный upsert сохраняет null | Отказ обоих кодировщиков и очистка значения через Receiver |
| Пустое обновление освежало старое наблюдение | Пустой элемент запрещён; любое partial сохраняет observed_ms | Атомарный отказ пустого элемента и отказ proposal после 40 секунд при лимите 30 секунд |
| ERR возвращался как err | Восстанавливается NAM kind error | Независимая JSON Schema и оба кодека |
| RESULT терял related, FAILED не работал, evidence терялись | Единый формат четырёх статусов с related и опциональной причиной | 16 комбинаций статуса, операций и причины внутри регрессионного теста |
| EXPLAIN добавлял запрещённый topic | Только поддерживаемый схемой запрос; старый topic/EXPLAINED явно отвергаются | Позитивный и негативный roundtrip |
| side/id/версия/точность могли теряться | Проверка сохранения всех переданных полей и явный отказ от неподдерживаемого ввода | Контрпримеры потери полей и различного округления Python/JS |
| Кодировщик мог создавать timestamp при неполном конверте | Обязателен полный конверт NAM; ошибки унифицированы как AMLError | Отказы при отсутствии времени, id, seq и session |
| Неизвестные schemas могли приниматься при пустом whitelist | Только пересечение с явно поддерживаемыми хостом схемами | Отказ hello с неизвестной схемой |
| selftest принимал правильный префикс как доказательство | Обычный контроль и два случайных маркера только в грамматике | Тестовые двойники игнорирующего и применяющего ограничение маршрута |
| Клиенты не различали нормальное завершение и обрыв | HTTP finish_reason; SDK result.stats.stop_reason | Обрывы, ошибки и отсутствие причины отвергаются в тестах |
| Базовый замер валидности вызывал только permissive decoder | Полный Lark-разбор и проверка NAM-схемы | Префикс, лишняя проза и неверные значения отвергаются |
| GBNF-тест ослаблял ограниченные повторы | Эквивалентное ограниченное развёртывание | 128/129 объектов, 3/4 действий и 63/64/65 символов hash |
| verify выдавал PASS для пропуска | Раздельные PASS/FAIL/SKIP и exit 0/1/2 | Полный журнал без SKIP при установленных зависимостях |
| AML delta сравнивался только с JSON full | Добавлено сравнение одинаковых дельт, transport policy отдельно | Новый лог реальных cl100k/o200k |

Исходные 43 Python-теста сохранены с исправлением недопустимых ожиданий и примеров. Добавлены 20 тестов: всего 63 Python-теста. Исходные 14 JS-тестов проходят; новые Python-тесты дополнительно вызывают JS-кодек и проверяют совпадение текстов и восстановленных объектов. GBNF и демонстрация проверяются отдельно. Авторитетный фактический результат — evidence/verify.txt.

## Повторное измерение токенов

> Исторический baseline поставки r1 (TOON 2.0.0); числа ниже не пересчитывались.
> В текущем пакете `@toon-format/toon` 2.3.1 (T16), результаты повторного замера —
> `review/2026-09-15/T16-antigravity-benchmark.txt`.

Токенизаторы: tiktoken 0.12.0, cl100k_base и o200k_base. TOON: @toon-format/toon 2.0.0. Все потоки имеют разделитель newline. Qwen не измерялся: transformers не установлен. Токенизаторы не являются запусками LLM.

| Сравнение | cl100k JSON → AML | Экономия cl100k | o200k JSON → AML | Экономия o200k |
|---|---:|---:|---:|---:|
| 10 полных состояний | 4920 → 3019 | 38.6% | 4920 → 3029 | 38.4% |
| Тот же поток с дельтами с обеих сторон | 1896 → 1115 | 41.2% | 1888 → 1125 | 40.4% |
| Один снимок роты | 808 → 448 | 44.6% | 809 → 447 | 44.7% |

Отдельно переход JSON full → JSON delta даёт 61.5% / 61.6% экономии в этом сценарии. При сравнении AML delta с JSON full эффекты складываются, но это не чистое преимущество записи AML.

Нельзя превращать эти результаты в доказательство ускорения prefill, снижения общего счёта или сохранения качества решений. Набор синтетический, небольшой и специализированный. Кодек проверяет заданные значения с допуском 1e-12 для float; отсутствие опциональных полей может нормализоваться в defaults. Битовая идентичность исходного JSON не заявляется.

## Неустранённые ограничения

1. Полная биекция и все возможности NAM в компактном формате не реализованы. Неподдерживаемое отклоняется; NAM JSON — путь сохранения исходных данных. Автоматический выбор транспорта не добавлен.
2. RESULT изменён, при этом исходный маркер AML:2 оставлен. Это кандидат для согласования профиля, не drop-in замена смешанной сети. Подробности — COMPATIBILITY.md. Нужны решение исходного агента о версионировании и согласованное обновление участников.
3. Partial updates теперь консервативны по свежести. Нет timestamp по каждому полю; новое наблюдение требует полного upsert. Это может увеличить трафик относительно прежнего ошибочного поведения.
4. Сам по себе AMLCodec.decode остаётся декодером ограниченной проекции. Для недоверенного модельного вывода нужен validate_frame, затем Receiver. Декодер не обещает отвергать все возможные лишние токены самостоятельно.
5. Нативная загрузка исходного GBNF, работа LM Studio/llama.cpp, задержки, качество решений, устойчивость к длительной нагрузке и весь игровой контур не проверялись.
6. SDK проверен по структурам wheel lmstudio 1.5.0 и тестовым двойникам. Проба с реальным сервером обязательна; другой SDK может отличаться.
7. Проверка schemas — разрешение объявленного номера, не механизм подгрузки предметного словаря. Язык остаётся специализированным.

## Состав передачи

- README — запуск и ограничения.
- docs/AGENT_HANDOFF.md — инструкция исходному агенту.
