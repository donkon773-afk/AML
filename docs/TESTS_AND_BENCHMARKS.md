# Тесты, бенчмарки и измерения AML/NAM

Здесь разделены автоматическая проверка реализации, замеры транспорта и эксперименты с генерацией моделей. Результаты относятся к указанным ревизиям/датам, оборудованию и наборам данных; они не являются универсальной гарантией.

## 1. Текущая офлайн-проверка

**Проверено 2026-10-02** на чистой временной копии исходников `HEAD` (чтобы тесты не затрагивали текущую локальную доску и незакоммиченные файлы). Команда: `python verify.py`, зависимости Python из `requirements-test.txt`, Node.js с зависимостями из lock-файла.

Краткий записанный протокол прогона: [`review/2026-10-02/GITHUB_VERIFY.md`](../review/2026-10-02/GITHUB_VERIFY.md).

| Контур | Результат |
|---|---|
| Python `unittest` | **150 тестов пройдены**; итог `OK` |
| JavaScript Node test runner | **14/14 пройдены** |
| GBNF эквивалентная проверка | **пройдена**: валидные/невалидные и усечённые кадры, границы повторов |
| Офлайн-демо | **пройдено**: валидный keyframe/proposal приняты, фиктивная цель и неполная строка отклонены |
| Общий шлюз | `OFFLINE PASSED`, код завершения `0` |

Python-набор включает кодеки, грамматики, схему NAM, Receiver, регрессии, `s:2`, файловую шину, публикацию STATE/DELTA, синхронизацию, ротацию и проверки шлюза. В ходе проверки `test_ci.py` также проверяет логику повтора временно падающей команды; итоговый прогон suite завершился успешно.

Проверка GBNF выполняется библиотекой-парсером через эквивалентно развёрнутые границы повторов. **Она не загружает и не проверяет нативный движок LM Studio/llama.cpp.** Offline suite не подтверждает живую работу сервера, реальное ограниченное декодирование, точность решений модели или production-развёртывание.

Для повторения следуйте командам в корневом [README](../README.md). `verify.py` возвращает `2`, если контур неполон (например, отсутствует Node или пакет GBNF); такой результат не следует записывать как успешную проверку.

## 2. Живое создание фреймов локальными моделями (2026-09-24)

Отчёт: [`review/2026-09-24/LIVE_FRAMES.md`](../review/2026-09-24/LIVE_FRAMES.md); сырые данные: `review/2026-09-24/live_frames_raw.json`. Выполнено **200 запросов**: по 20 на пять типов (`HANDOFF`, `RES`, `QUERY`, `ERR`, `PROP`) для каждой из двух конфигураций. Для кластерного acceptance-порога учитываются первые четыре типа; `PROP` — отдельный профиль и справочный результат.

| Модель/режим | Кластерные типы, strict | Lenient | Receiver accept | Семантика | p95 генерации |
|---|---:|---:|---:|---:|---:|
| qwen3.5-9b, SDK + GBNF | 80/80 = **100%** | 100% | 100% | 100% | ≤ 5.45 с |
| gemma-4-12b-coder, HTTP freeform | 72/80 = **90%** | 100% | 100% | 100% | ≤ 12.45 с |

Здесь `strict` означает, что весь вывод без извлечения/исправления проходит проверку. У `gemma` на `RES` strict был **12/20 = 60%**: восемь раз модель добавила пояснение второй строкой после корректного фрейма; `extract_frame` принял первую строку. Это ниже целевого strict-порога 80% для данного отдельного типа и требует явно включённого lenient-пути или корректной stop-последовательности.

В справочных `PROP` замерах qwen достиг 17/20 (85%) semantic, gemma — 18/20 (90%). Результаты PROP не включаются в кластерный порог. Измерения показывают формат, приём и задержку на конкретной конфигурации; они не подтверждают качество всех решений и переносимость на другие машины/версии.

## 4. Компактность и трафик

### Реальный снимок доски `s:2` (T37, 2026-09-24)

Для снимка с 15 задачами и 4 агентами:

| Представление | Размер |
|---|---:|
| AML `s:2` | 1 014 байт / 496 токенов `cl100k_base` / 496 токенов `o200k_base` |
| NAM JSON | 2 778 байт / 891 токен `cl100k_base` / 863 токена `o200k_base` |
| Разница | −63.5% байт / −44.3% `cl100k_base` / −42.5% `o200k_base` |

### Ночная лента STATE/DELTA (T38, выборка на 2026-09-24)

Для 14 кадров (1 STATE и 13 DELTA) записано 3 786 байт AML против 9 899 байт JSON (**−62% байт**). Для токенов сообщён результат 1 657 против 2 859 (**−42%**), но токены были доступны не для всех кадров до перезапуска на среде с `tiktoken`; это частичная выборка. DELTA медиана составила 139 байт, максимум 452 байта; STATE с 23 строками — 1 229 байт.

Главный механизм уменьшения трафика здесь — **передавать DELTA вместо полного повторного снимка** и не публиковать неизменившуюся доску, а не только сокращать написание полей.

### Эталонный компактный набор

Сценарные документы приводят историческое сравнение 919 байт AML против 1 812 байт JSON (−50%). Читайте его как результат конкретного набора примеров, а не универсальный процент для любых сообщений. Отдельный отчёт о сравнении с TOON: `review/2026-09-15/T16-antigravity-benchmark.txt`.

## 5. Что замеры пока не доказывают

- Универсальное уменьшение токенов/байтов для произвольных диалогов.
- Корректность смысла каждого решения, которое предложила LLM.
- Защиту от подмены отправителя: текущая файловая реализация не подписывает кадры.
- Безопасность работы в недоверенной сети или межмашинную авторизацию.
- Задержки и качество на иной модели, квантизации, prompt, backend или аппаратуре.
- Поддержку GBNF в конкретной версии нативного движка, если не выполнена отдельная живая probe-проверка.
