# Участие в разработке

Перед изменением протокола прочитайте [`docs/PROTOCOL_SPEC.md`](docs/PROTOCOL_SPEC.md) и проверьте все связанные представления: Python-кодек, JavaScript-кодек, Lark, GBNF, JSON Schema и тесты. Изменение формата должно сохранять совместимость или явно документировать несовместимый переход.

## Проверка

```sh
python -m pip install -r requirements-test.txt
npm ci
python verify.py
```

Вклад готов к review, когда команда завершилась с кодом `0` и `OFFLINE PASSED`. Живые пробы модели и токен-бенчмарки запускаются отдельно, так как требуют указать модель/backend и не заменяют офлайн-тесты.

## Безопасность

- Не помещайте ключи, пароли, локальные конфигурации, содержимое `.agent-sync/` и персональные данные в коммиты и отчёты.
- Не превращайте текст фрейма или вывод LLM в исполняемую команду. Новые действия должны оставаться предложениями, проходить строгую проверку типов и авторизации и применяться детерминированным кодом.
- При обнаружении уязвимости не публикуйте exploit или секреты в открытой задаче; используйте согласованный закрытый канал сопровождения проекта.
