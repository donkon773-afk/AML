# AML/NAM

**AML/NAM** — компактный wire-протокол для обмена структурированными сообщениями между агентами и локальными программами. Репозиторий содержит спецификацию, кодеки Python и JavaScript, грамматики Lark и GBNF, схему NAM/2, приёмник, пример файловой шины, тесты и воспроизводимые отчёты.

> **Статус:** исследовательский прототип и пилотный транспорт. Есть офлайн-валидация и ограниченные измерения локальных моделей. Для межмашинной работы требуется добавить аутентификацию и защищённый транспорт; текущая файловая шина рассчитана на локальную среду.

## Что находится в репозитории

| Компонент | Расположение |
|---|---|
| Кодек AML | `scripts/aml_codec.py`, `scripts/aml_codec.js` |
| Формальная грамматика | `scripts/aml_grammar.lark`, `docs/aml_v2.gbnf` |
| Схема NAM/2 | `assets/nam.schema.json` |
| Семантическая проверка и Receiver | `scripts/frame_validation.py`, `scripts/nam.py` |
| Файловая шина и публикация доски | `scripts/aml_bus.py`, `scripts/board_frames.py` |
| Автоматические проверки | `tests/`, `verify.py` |
| Генерация/измерение трафика | `scripts/benchmark_*.py`, `scripts/bench_bus.py` |

В NAM/2 общий конверт отделён от полезной нагрузки. Базовые сообщения кластера — `HANDOFF`, `RES`, `QUERY`, `ERR`; `STATE`, `DELTA` и `PROP` обслуживают структурированные снимки, изменения и предложения действий. Профиль кластера помечается `s:2` и не смешивает task/agent-словарь с тактическим словарём другого профиля.

## Установка и офлайн-проверка

Требуются Python 3.10+ и Node.js 18+. Проверки не запускают модели и не обращаются к серверам.

```sh
python -m venv .venv
# Linux/macOS:
. .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements-test.txt
npm ci
python verify.py
```

Код завершения `0` означает, что все включённые офлайн-проверки завершились успешно; `1` — обнаружен провал; `2` — проверка неполна из-за отсутствующей зависимости или инструмента. `SKIP` не является успешным результатом. Скрипт печатает фактические количества тестов для текущей ревизии.

## Пример фрейма

```text
!AML:2|RES|aml-nam|codex→claude|2|1790200601000|60000|rel:T13|*REJ:#T13|rs:CRITIC_RETURN

```

Первая строка содержит версию, тип, сессию, отправителя и адресата, порядковый номер, время отправки, TTL и полезную нагрузку. Пустая строка завершает сообщение в файловом транспорте. См. [спецификацию](docs/PROTOCOL_SPEC.md), прежде чем строить совместимый парсер.

## Ограничения и безопасность

- TTL ограничен 60 000 мс текущей схемой; устаревшие сообщения должны отклоняться.
- `Receiver` проверяет структуру, профиль, полномочия типа сообщения, свежесть и повторы. Интеграция с доской дополнительно проверяет роль отправителя по текущему состоянию задачи.
- Локальные модели могут выдавать предложения/вердикты, но не получают автоматического права менять состояние доски.
- Файловая шина и проверка личности по имени outbox не являются сетевой аутентификацией. Не открывайте её в недоверенную сеть. Для многомашинного применения нужны подпись сообщений (например, HMAC с управлением ключами), защищённый транспорт, модель угроз и отдельная проверка реализации.
- Ограниченная грамматика не гарантирует правильность смысла или безопасность предложенного действия. Решения проверяются программным Receiver и политикой приложения.
