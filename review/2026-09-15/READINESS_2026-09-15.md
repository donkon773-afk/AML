## Термин

Проект называется **AML — компактный протокол межагентного обмена
(A2A wire protocol)**: формат сериализации сообщений с формальной
грамматикой (Lark/GBNF) и схемой (NAM JSON Schema), по которому
обмениваются агенты одного кластера. Прежнее название «машинный язык для
ИИ-агентов» (заголовок `AML_A2A_CURATOR_SPEC.md`) — устаревшее: оно
отсылает к системе команд процессора, тогда как AML — протокол обмена,
а не язык исполнения. В новых документах используется только новый термин.

## Главная развилка

Если гипотеза по STATE подтвердится (Codex поручены две контр-пробы:
грамматика с повтором `{1,2}` и короткий PROP-фрейм), то:

- **STATE/DELTA** (описание обстановки, много строк) должны кодироваться
  **детерминированно** источником данных через `AMLCodec.encode`, а не
  генерироваться моделью;
- **модели** остаются короткие фреймы решений — **PROP/QUERY/RES/ERR** —
  с жёстко ограниченными повторами в грамматике;
- сжатие токенов (38–45 % против JSON по замерам r1) достигается на
  входе модели, а не на выходе.

Для протокола межагентного обмена это не потеря, а уточнение: большая часть
трафика в кластере — состояния и дельты, которые пишут программы, а не LLM.

Если гипотеза **не** подтвердится (короткий PROP тоже не завершается) —
целевой файнтюн `hauhaucs-aggressive` непригоден для генерации AML вообще,
и пробы нужно повторить на модели с управляемым reasoning (Qwen 3.5 без
файнтюна / `qwen3.5-2b` / Ministral) до любых архитектурных выводов.

## Что «готово», что нет

Готово к использованию **сейчас**: кодек как библиотека (encode/decode,
validate_frame, Receiver) для программного обмена между агентами — без
участия LLM. Именно это можно применить к нашему же кластеру: доска, лог
и почта трёх агентов — первый реальный потребитель протокола (см. T17).

Не готово: генерация фреймов моделью (кроме проб), любые заявления о
скорости/стоимости полного конвейера, работа на серверах кроме LM Studio
0.4.24 (HTTP-маршрут — только с маркерной пробой).
