## 1. Что проверено

### 1.1. Логика расхода лимитов и шкала времени (`scripts/spend.py`)
- **Учёт падения % лимитов**:
  - `limit_spend` корректно фиксирует только снижения остатка окна 5 ч (`pct5h`) и недельного окна (`pctweek`) между соседними замерами агента (события `heartbeat` и `limits`).
  - Восстановление квоты ($c \ge p$) расходом не считается (сброс окна).
  - Чтение событий объединяет архивы ротации `archive/events-*.jsonl` и активный `events.jsonl` с дедупликацией строк и хронологической сортировкой.
- **Привязка к задаче (`Timeline`)**:
  - `timeline.task_at(agent, t)` находит последнюю задачу агента через `bisect_right`.
  - Задачи «-» или пустые нормализуются в `None` и отображаются как «—».
  - Разрывы между пульсами $> \text{window\_min}$ (по умолчанию 60 мин) отсекаются от атрибуции к задаче и направляются в «—» (вне пульса), исключая ложные списания.

### 1.2. Учёт токенов Claude Code и Codex
- **Claude Code (`claude_tokens`)**:
  - Фильтрация сессий по маркеру `aml-nam` исключает влияние сторонних репозиториев.
  - Дедупликация потоковых чанков по `message.id` / `requestId` / `uuid` предотвращает многократный учёт одной и той же генерации.
  - По тарифам `CLAUDE_PRICES` раздельно тарифицируются обычный вход, запись кэша (5 мин и 1 ч), чтение кэша и выход.
- **Codex (`codex_tokens`)**:
  - Накопительный счётчик `total_token_usage` корректно пересчитывается в межпошаговые дельты.
  - Расчёт эквивалента в ценах Claude (`REFERENCE_MODEL = opus-5-5`) позволяет сопоставлять вклад агентов на единой шкале.

### 1.3. Команда CLI `agent_sync spend`
Проверена работа CLI на реальных логах проекта:
- `python scripts/agent_sync.py spend --hours 24` — форматированный текстовый отчёт с группировкой по агентам и задачам.
- `python scripts/agent_sync.py spend --hours 1 --json` — валидный машиночитаемый JSON со структурой `agents`, `tasks`, `claude_eq_shares`.
- `python scripts/agent_sync.py spend --no-tokens` — быстрый режим только по пульсам лимитов без сканирования журналов токенов.
- `python scripts/agent_sync.py spend --since 2026-09-24T10:00:00` — фильтрация по ISO-дате.
- Интеграция в ночной отчёт `cmd_report` обёрнута в `try...except`, что защищает формирование отчёта при недоступности логов.

### 1.4. Исправление `set weight=int`
- В `cmd_set` добавлено приведение `elif k in ("priority", "weight"): t[k] = int(v)`, исключающее ошибку сложения строк в `readiness()` при расчёте готовности вех.
