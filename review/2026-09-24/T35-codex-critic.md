## F1 — неполный фрейм теряется без повтора

`receive()` читает файл целиком, разбивает текущий хвост по началу `!AML:2|` и заранее ставит `offsets[fp.name] = len(raw)`. Нет проверки завершённости фрейма перед `handle()`. Изолированная проба: создать HANDOFF `antigravity → T90 COMPLETE`, оставить в outbox только строку заголовка (имитация чтения посреди append), вызвать `receive()`, затем дописать оставшиеся строки и вызвать `receive()` снова. Получено: сначала `reject ... ERR INVALID: string length`, затем `reject ... ERR INVALID: Invalid or incomplete AML syntax`; T90 осталась `in_progress`, полноценный фрейм никогда не принят. Это возможно при записи несколькими системными вызовами, краткой записи или падении отправителя.

Нужно сохранять только смещение последнего **полностью законченного** фрейма и держать неполный хвост до следующего прохода, либо отправлять фрейм атомарным rename готового файла. Добавить тест записи двумя частями с вызовом `receive()` между ними: без отказа на первом проходе, один переход в `review` после дописывания.
