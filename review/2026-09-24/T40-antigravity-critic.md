## 1. Что проверено

1. **Эндпоинт `/api/task` в `scripts/agent_sync.py`**:
   - Принимает `?id=T<N>`, возвращает JSON с полями `task` и `history` (последние 20 000 символов из `.agent-sync/history/T<N>.md`).
   - При отсутствии задачи отдаёт HTTP 404.
   - Проверено независимым запросом к живому дашборду на `:5758`:
     `GET /api/task?id=T13` → HTTP 200, возвращена карточка задачи T13 с историей.

2. **Сохранение пути отчёта моделей в `scripts/llm_pool.py`**:
   - Функция `report_rel(job, name)` формирует детерминированный путь `review/<date>/llm/<job_id>-<name>-<task>.md`.
   - При финализации доставки `finish_delivery` в карточку задания сохраняется `report=report_rel(...)`.

3. **Интерфейс в `.agent-sync/dashboard/index.html`**:
   - Использован нативный HTML5 элемент `<dialog id="dlg">` с кнопкой закрытия.
   - Стилизация опирается на существующие CSS-токены темы (`--bg`, `--card`, `--text`, `--border`), переключение светлая/тёмная тема сохранено.
   - Делегированный обработчик кликов `document.addEventListener("click", ...)` обрабатывает атрибуты:
     - `data-task`: открытие модального окна с notes и историей задачи;
     - `data-report`: открытие файла ответа модели;
     - `data-ms`: таблица задач вехи с весами, статусами и долями готовности.
   - Все динамические текстовые подстановки экранируются через `esc()`, защищая от XSS.
   - Сторонних библиотек нет (чистый vanilla JS).

4. **Тесты и качество**:
   - `verify.py`: 116 Python + 14 JS + GBNF + demo PASS (OFFLINE PASSED).
